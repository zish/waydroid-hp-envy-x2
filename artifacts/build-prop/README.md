# build.prop device identity — a disproven experiment

**Not deployed.** Kept because the mechanism is non-obvious and the traps are expensive to
rediscover. The hypothesis it tested — that Netflix rejects this device on identity — is
**disproven**; see [../../docs/22-netflix-container-detection.md](../../docs/22-netflix-container-detection.md).

## Layout

```
original/   the seven build.prop files exactly as the images ship them
modified/   generated by make-identity.py; gitignored-in-spirit, regenerate rather than edit
make-identity.py
```

`original/` is the authoritative copy of stock values. Re-pull with:

```bash
for f in /system/build.prop /system/system_ext/etc/build.prop /system/system_dlkm/etc/build.prop \
         /system/product/etc/build.prop /vendor/build.prop /vendor/odm/etc/build.prop \
         /vendor/odm_dlkm/etc/build.prop /vendor/vendor_dlkm/etc/build.prop; do
  name=$(echo "$f" | sed 's|^/||; s|/|_|g')
  ssh 10.42.0.137 "sudo waydroid shell -- sh -c 'cat $f' 2>/dev/null" \
    | grep -v "Errno 13\|details-to-stdout\|See also:\|/usr/sbin/waydroid" > "original/$name"
done
```

## What it does

Presents the device as ChromeOS `nissa` running ARCVM Android 13:

```
google/nissa/nissa_cheets:13/R130-16033.58.0/12608590:user/release-keys
```

Chosen because it is genuinely x86_64, is SDK 33 like this container, and is the very device the
installed Widevine CDM was extracted from — so the CDM's device certificate and the build identity
agree. Edit the constants at the top of `make-identity.py` to target something else.

## Deploying (if ever wanted again)

```bash
python3 artifacts/build-prop/make-identity.py
# stage into overlay layout, then:
tar -cf - --owner=0 --group=0 -C <stage> . \
  | ssh 10.42.0.137 'sudo tar -xf - -C /var/lib/waydroid/overlay/'
ssh 10.42.0.137 'sudo systemctl restart waydroid-container'
```

Overlay paths: `overlay/system/...` serves `/`, `overlay/vendor/...` serves `/vendor`.
`/odm`, `/odm_dlkm` and `/vendor_dlkm` are the same inodes as their `/vendor/...` counterparts, so
the vendor overlay reaches all three.

## Reverting

Delete what was added and restart — no image is touched:

```bash
ssh 10.42.0.137 'sudo rm -rf /var/lib/waydroid/overlay/system \
  /var/lib/waydroid/overlay/vendor/build.prop \
  /var/lib/waydroid/overlay/vendor/odm \
  /var/lib/waydroid/overlay/vendor/odm_dlkm \
  /var/lib/waydroid/overlay/vendor/vendor_dlkm'
```

Be careful not to delete the rest of `overlay/vendor/` — `bin/hw`, `lib`, `lib64` and `etc` there
hold the camera, health-HAL and Widevine fixes, which are all live and wanted.

## The three traps

1. **`waydroid_base.prop` cannot do this.** Read-only properties cannot be re-set once a
   `build.prop` defines them.
2. **`ro.product.*` is derived and odm wins** (`ro.product.property_source_order` is unset, so the
   default `odm,vendor,product,system_ext,system` applies). Editing `/system/build.prop` alone
   changes nothing observable. `ro.build.fingerprint` is in no `build.prop` at all — init derives it.
3. **Miss one partition and Android accuses the device.** Leaving `vendor_dlkm` stock produced a
   system dialog on every boot: *"There's an internal problem with your device. Contact your
   manufacturer for details."* Its text never reaches logcat — take a `screencap`.
