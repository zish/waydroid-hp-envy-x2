Offline check of the synthesised information elements.

The IE blob is the one invented part of Stage 3 -- everything else is
either copied from the host or read out of the image.  So it is checked
without a device: the daemon's buildBeaconIes() is compiled standalone,
fed one Bss per security type, and the bytes are run back through a
reimplementation of Android's InformationElementUtil (parseInformationElements,
parseRsnElement, parseWpaOneElement, generateCapabilitiesString) to see
what capability string the framework would build.

Sources: scratchpad ietest.cpp + decode.py, from AOSP android-13.0.0_r75
packages/modules/Wifi InformationElementUtil.java.

Confirmed on device afterwards -- 'cmd wifi list-scan-results' agrees,
except that the framework's WPA2 back-compat duplicate lists only the
WPA2-valid AKMs ([WPA2-PSK-CCMP] beside [RSN-PSK+SAE-CCMP]) where this
decoder copies the whole string.  The RSN half, which is the one that
matters, matches exactly.
