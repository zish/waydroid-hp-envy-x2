# Custom Waydroid LXC configuration, and what these packages need from it

Waydroid runs Android in an LXC container whose configuration lives in
`/var/lib/waydroid/lxc/waydroid/`. Several packages in this project depend on specific things
in there being true. If you have customised that configuration — or if you use a Waydroid
setup that generates it differently — this page tells you what to keep.

**Waydroid regenerates these files.** `waydroid init`, `waydroid upgrade` and starting a
session each rewrite some or all of them. Edits you make by hand are *not* durable, and this is
the single most common reason something that worked last week stops working today.

| File | Regenerated by | Safe to edit? |
|---|---|---|
| `config` | `waydroid init`, `waydroid upgrade` | edits are lost on upgrade |
| `config_nodes` | every container start, from what exists on the host | no — rewritten each time |
| `config_session` | every session start | no — rewritten each time |
| `waydroid.seccomp` | `waydroid init` | no |

## What each package needs

### The host daemons need the binder nodes bind-mounted

`waydroid-ext-sensord` (sensors, screen brightness) and `waydroid-ext-wifid` (Wi-Fi) are
**host** processes that register services inside Android's binder namespace. That is only
possible because Waydroid bind-mounts the binder device nodes into the container:

```
lxc.mount.entry = /dev/binder    dev/binder    none bind,create=file,optional 0 0
lxc.mount.entry = /dev/vndbinder dev/vndbinder none bind,create=file,optional 0 0
lxc.mount.entry = /dev/hwbinder  dev/hwbinder  none bind,create=file,optional 0 0
```

Note `optional` — if the node is missing on the host, LXC starts the container anyway and the
line silently does nothing.

**If your host uses a single-node binder driver** (one `/dev/binder` with no `vndbinder` or
`hwbinder`, as some kernels and some `binder_linux` configurations provide), the sensors and
brightness daemon has nothing to register on and will fail to appear. Check with:

```bash
ls -l /dev/binder /dev/vndbinder /dev/hwbinder
```

**If the binder protocol does not match**, services register but nobody finds them. Waydroid
records what it detected in `/var/lib/waydroid/waydroid.cfg`:

```
binder_protocol = aidl3
service_manager_protocol = aidl3
```

The daemons read those values. If you have overridden them by hand, override them correctly.

### Wi-Fi needs the container's interface named `wlan0`

```
lxc.net.0.name = wlan0
```

Waydroid's default is `eth0`. Android's connectivity stack scores an interface it believes is
Ethernet above one it believes is Wi-Fi, so with the default name Android will associate with a
network, report it as connected, and then route all traffic over the Ethernet-looking interface
instead — which looks like "Wi-Fi connects but nothing works."

`waydroid-ext-lxc-config` sets this before the container starts, on every boot, precisely
because `waydroid upgrade` erases it.

**If you have customised networking** — `lxc.net.0.type = none` to share the host's network
namespace, a bridge of your own, or more than one `lxc.net.N` stanza — this package's
assumption that there is exactly one interface to rename does not hold. Uninstall it and set
the name yourself, or rename whichever interface carries Android's default route.

### Removable media needs mount propagation left alone

`waydroid-ext-media` mounts USB sticks and cards **on the host**, inside the Waydroid data
directory, and relies on that mount propagating into the container by itself. That works
because the data directory's parent is a `shared` mount and Waydroid's LXC configuration sets
no propagation options on it.

**If you have added `private` or `slave` propagation**, or bind-mounted the Waydroid data
directory through something that does, volumes will mount on the host and simply never appear
in Android. Nothing errors. Check with:

```bash
findmnt -o TARGET,PROPAGATION ~/.local/share/waydroid/data
```

`shared` is what you want.

### The camera needs its video node bind-mounted

```
lxc.mount.entry = /dev/video0 dev/video0 none bind,create=file,optional 0 0
```

`config_nodes` is generated at container start from the video devices that exist on the host at
that moment. **A camera plugged in after the container started is not in the container**, and
no amount of overlay payload changes that — restart the container after plugging it in.

Also note the node must be readable by Android's `cameraserver`, which runs as an unprivileged
Android uid with no id mapping to your host user. In practice this means the device must be
world-readable on the host; a `video`-group-only device will not work.

### The app freezer needs a writable cgroup mount, which Waydroid does not give it

```
lxc.mount.auto = cgroup:ro sys:ro proc
```

Android's per-app freezer and compaction need to write to `/sys/fs/cgroup` inside the
container, and that mount is read-only. This is why those features are off and why turning them
on in Android's settings alone does nothing. Changing `cgroup:ro` to `cgroup:rw` has not been
validated here and is not something any package does for you.

## If you run a modified Waydroid

Things that will need attention:

- **A different image source or Android version.** The overlay components are built against
  Android 13 (API 33) `MAINLINE` images. A `GAPPS` image is fine; a different Android version is
  not — several components are prebuilt binaries whose interfaces are version-specific, and they
  will either be ignored or crash the service that loads them.
- **`mount_overlays = False`** in `/var/lib/waydroid/waydroid.cfg`. With overlays off, Waydroid
  never mounts `/var/lib/waydroid/overlay` at all and **none** of the Android-side packages do
  anything. `waydroid-overlay-sync` warns about this on every run.
- **A hand-built container config that does not `lxc.include` `config_nodes`.** Everything above
  that depends on a bind mount stops being true at once.

## Checking

```bash
sudo waydroid-overlay-sync --verify      # is the overlay what the packages expect?
cat /var/lib/waydroid/waydroid.cfg       # overlays on? which binder protocol?
sudo cat /var/lib/waydroid/lxc/waydroid/config
findmnt -o TARGET,PROPAGATION ~/.local/share/waydroid/data
```

See [overlay.md](overlay.md) for how the Android-side changes are applied and for the three
ways they can appear to stop working.
